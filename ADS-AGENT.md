# ИИ-агент рекламы Wildberries

`ads-agent.mjs` дважды в день (06:17 и 15:17 мск, workflow «ИИ-агент рекламы WB») смотрит на каждую рекламную кампанию WB и решает: оставить, снизить или поднять ставку, поставить на паузу, закрыть насовсем. Решения и их причины видны в дашборде, вкладка «Реклама» → «ИИ-агент рекламы», и в файле `ads-agent.json`.

## Как он считает

- **Маржа до рекламы** — прибыль товаров кампании без учёта рекламы, делённая на выручку, за 30 дней (Торгстат, `data.json`). Это потолок: выше него каждый рекламный заказ в минус.
- **ДРР** — расход на рекламу, делённый на выручку с рекламных заказов с поправкой на процент выкупа (статистика кабинета WB, `market.json`). Считается за 30, 14 и 7 дней.
- **Цель** — `targetShare` от маржи (по умолчанию 60%), но не больше `maxDrr` (25%).

| Ситуация | Действие |
|---|---|
| ДРР выше цели | ставка вниз, не больше `bid.maxStepPct` за раз |
| ДРР ниже 70% цели, есть заказы и остаток | ставка вверх на `bid.upStepPct` |
| ДРР выше маржи × `stop.overMarginFactor` и за 30, и за 14 дней | закрыть |
| Товар убыточен ещё до рекламы | закрыть |
| Потрачено больше `stop.noOrdersSpend`, заказов нет | закрыть |
| Товара нет на складе | пауза; агент сам включит, когда товар вернётся |
| Мало данных (`minSpend`, `minClicks`) | ждать |

Если в секретах репозитория есть `ANTHROPIC_API_KEY`, решения принимает Claude: он видит те же цифры, тренд, остатки, рейтинг и свои прошлые действия. Без ключа работают правила из таблицы. В обоих случаях решение проходит одни и те же жёсткие ограничения в коде: закрыть можно только кампанию, убыточность которой подтверждена цифрами; шаг ставки, её пол и потолок ограничены; ставку одной кампании не меняют чаще раза в `bid.cooldownHours`; за запуск закрывается не больше `stop.maxPerRun` кампаний.

## Включение

1. Сейчас в `ads-agent.config.json` стоит `"mode": "dry-run"`: агент только пишет план, в кабинете ничего не меняется. Посмотрите план в дашборде.
2. Токены WB (`WB_SAKOVSKY_TOKEN`, `WB_DARMIL_TOKEN`) должны иметь категорию «Продвижение» **с правом записи**. Токен только на чтение даст план, но не изменения.
3. Для решений от Claude добавьте секрет `ANTHROPIC_API_KEY` (Settings → Secrets and variables → Actions).
4. Чтобы агент начал менять кампании, поставьте `"mode": "live"`. Разовый запуск в любом режиме: Actions → «ИИ-агент рекламы WB» → Run workflow.

Закрытие кампании в WB необратимо: закрытую нельзя запустить снова, только создать новую. Кампании, которые трогать нельзя, перечислите в `protect` (номера кампаний).

## Что выключено по умолчанию

- `launch.enabled` — создавать кампании для прибыльных товаров без рекламы (маржа до рекламы от `minMargin`, остаток от `minStock` шт. и не меньше чем на `minStockDays` дней продаж, продажи от `minSales30` за 30 дней, рейтинг от `minRating`) и сразу пополнять их на `launch.budget` ₽. Всего агент запускает не больше `maxTotal` кампаний за всё время и не перезапускает товар, если его кампанию он уже закрыл.
- `budget.autoTopUp` — пополнять окупающиеся кампании на `topUpSum` ₽, не больше `dailyCap` ₽ в день. `source`: 0 — счёт, 1 — баланс, 3 — бонусы.

Обе настройки тратят деньги с рекламного счёта, поэтому включаются отдельно.

Реклама Ozon и Яндекс Маркета агентом не управляется: для Ozon нужен отдельный ключ Performance API.

Проверка логики: `node ads-agent.test.mjs`.

## Отчёт в Telegram

Каждый вечер в 21:00 мск workflow «Отчёт агента рекламы в Telegram» присылает картинку: что агент закрыл, запустил, где менял ставки, сколько экономит в день, как идут его новые кампании, плюс скриншот блока агента с дашборда.

1. В Telegram откройте @BotFather → /newbot, придумайте имя. Он пришлёт токен.
2. GitHub → Settings → Secrets and variables → Actions → New repository secret: `TELEGRAM_BOT_TOKEN` = токен.
3. Откройте своего бота и нажмите «Старт».
4. Actions → «Отчёт агента рекламы в Telegram» → Run workflow. Первый отчёт придёт в чат, бот пришлёт номер чата: добавьте его секретом `TELEGRAM_CHAT_ID`.

Проверить вид отчёта без отправки: `node ads-report.mjs --html` → `ads-report.html`.
